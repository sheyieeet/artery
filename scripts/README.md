The corrected inputs and populations are:

- PRR uses `cpmLinkPrr.all.distance*` scalar counts: received / resolved, with resolved = received + failed. Departure and termination censoring are excluded. The `all` scope already pools VV, VR, RV, and RR; adding the four role scopes again would double-count. Each point is a 25 m bin over transmitter–receiver distance 0–500 m. Ratios are computed after pooling counts, never by averaging ratios. Empty resolved bins are gaps.
- **Scalars describe the whole recorded measurement period.** `--start`/`--end` filter vectors only; they cannot time-filter PRR or coverage scalars. Match the recorded scalar period to the desired experiment period. Existing short runs must not be presented as full-run measurements.
- The primary CDF uses only `cpmPhysicalObjectFreshUpdateIntervalVehicle`; RSU CDFs use the separate `...Rsu` signal. These are CPM-only physical-object fresh-information arrival intervals, pooled across vehicle receiver–object streams and reporters, conditional on completed intervals. Distance eligibility is physical object–receiver 0 < d <= 500 m, distinct from PRR's transmitter–receiver distance. Repeated/older information is already excluded by the observer. No legacy object-ID interval is substituted.
- `freshness_coverage.tsv` and coverage bar charts accompany the CDFs with zero-, one-, and at-least-two-update episodes. The table also retains zero-exposure episodes, eligible seconds, completed initial waits/intervals, censored initial waits/gaps, and censored seconds. Zero-exposure episodes remain separately identifiable; the coverage chart includes them in its episode denominator. These are receiver–object eligibility episodes, not counts of distinct lifetime objects. CDFs alone cannot rank methods fairly when coverage differs. Censored intervals are not inserted as completed intervals or zeros.
- `cpmPacketSize` samples are encoded application-payload bytes for actual application submissions, including relays. They exclude network headers and suppressed decisions. `transmission:vector` has cumulative values: its **sample count**, not the sum of its values, measures submissions. These are not confirmed radio transmissions. `cpmTxObjectCount` values count encoded entries, including zero-entry packets and the encoder's 255-entry limit; sums count repeated entries in forwarded packets too.
- TX rates join `cpmTxWindowBytes` to `cpmTxWindowDuration` by run, station module, and window end. Zero-byte active windows and partial entry/departure/finish windows are retained. Every byte is weighted with its actual duration. The per-active-station rate is `8 sum(bytes) / sum(station-active seconds)`. Total network rate uses observed run-wall seconds instead; pooled replicate runs average their network exposure rather than summing independent networks. Network wall exposure runs from the selected `--start` through the latest recorded window end in each run (capped at `--end`). Initial silence before the first station enters counts as zero network traffic; station exposure starts only when a station is active. Internal periods with no active station also have zero network traffic, while per-active-station rates are undefined. Choose `--start` at or after warm-up and `--end` at the actual recorded run end. Results lack explicit run-end metadata: if every station departs early, wall time after the final station window cannot be inferred and is reported unavailable. Road 120 RSUs remain active to termination, so its last window supplies the run end.
- Plot bins use accounting's right-closed convention: a submission exactly at a boundary belongs to the window ending there; the initial selected endpoint is included. If a plot boundary cuts a recording window, bytes in affected bins are rebinned exactly from corrected `cpmPacketSize` events, while exposure still comes from window durations. This is reported; byte traffic is never assumed uniformly distributed within a window. Missing station/run identity in CSV-R prevents trustworthy window joining; supply native `.vec` or complete CSV-R metadata.
- Existing channel-load, perception-rate, and received-object comparisons remain. RX throughput and received-object counts are explicitly labeled **legacy** descriptive measurements: their measurement implementations were outside this change. Perception-rate plots show recorded observation means, without error bars masquerading as confidence intervals. None of these are used as substitutes for corrected TX metrics, PRR, or freshness.

`measurement_summary.json` reports exact counts, sources, populations, exposure, per-bin rates, missing metrics, and warnings. Corrected metrics are never silently replaced with legacy signals. Declared but empty freshness vectors are retained in availability reports. Packet/CDF reservoirs retain at most `--sample-cap` observations; all totals and means use all observations. Larger CDFs and boxplots are uniform-sample approximations. There are no fabricated vertical guide lines or inferred confidence intervals. Multiple runs are pooled, not treated as independent per-packet replicates for statistical inference.

Text `.vec` and CSV-R are read incrementally. CSV fields spill to disk above 64 KiB. A temporary SQLite database joins only fixed-window summaries (no packet histories), with a 2 MiB cache. RAM scales with vector declarations, plot bins, and reservoir limits, not packet count. Temporary disk space scales with selected station windows; `--temp-dir` chooses its location. Native SQLite OMNeT++ result files and CSV-S summaries are not supported; use original text results or CSV-R exports. Run-time dependencies are listed in `requirements-plotting.txt`.
